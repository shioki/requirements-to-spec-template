# プロンプト例: 仕様書の曖昧語をレビューする

既存の要求仕様書から、テストできない文と未整理の未確定事項を洗い出すときに使います。判定基準は [`docs/writing-guide.md`](../writing-guide.md) です。

```text
あなたは要求仕様のレビュアーです。次の要求仕様書を読み、曖昧な記述だけを指摘してください。仕様の書き換え案は、指摘ごとに1つまでにしてください。

指摘する対象:
- 「適切に」「なるべく」「可能な限り」など、Yes/No で判定できない語
- 主語が無く、誰が何をするか分からない文
- 機能要求が「[条件/トリガー] のとき、システムは [動作] する」になっていない文
- 機能要求一覧にある機能-XX に受け入れ基準が無いもの
- 本文に残っている未確定事項(未解決-XX へ切り出すべきもの)。担当者または期限が空の未解決-XX、判断記録が空の解決済の未解決-XX も含む
- 非機能要求で、目標値・測定条件・測定方法のいずれかが空のもの
- 非機能要求にアクセシビリティ(適合レベルと試験方法)または対応環境(ブラウザ・OS・画面幅)が無いもの
- 受け入れ基準の異常系で表示する文言が 文言-XX として決まっていないもの
- 役割・権限に未ログインの利用者の行が無いもの
- 画面詳細の主要要素で、DADS のコンポーネント名も「独自」も書かれていないもの

指摘しないもの:
- テンプレートの空欄そのもの(まだ記入前の表の空セル)
- メモに無い数値を埋める提案

出力形式:
| 箇所 | 問題 | 書き換え案 |
| --- | --- | --- |
| (見出しまたは ID) | (判定できない理由) | (1文の修正案。未確定なら未解決-XX への切り出し案) |

対象の要求仕様書:
(ここに仕様書を貼る)
```
